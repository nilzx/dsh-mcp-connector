# MCP 连接器

把 MCP 服务器接到 DeepSeek Harness 里，让智能体能直接使用它们的工具。支持本地命令、远程地址和 OAuth 登录，并且可以为每个工具单独设置智能体能做什么。

English: [README.md](README.md)

## 开始之前

- 已安装 DeepSeek Harness（dsh）。
- 如果服务器是本地命令，需要先装好对应的命令（例如 `npx`）。

## 安装

1. 打开 **设置 → 插件**。
2. 选择 **添加插件**，填入 `@nilzx/dsh-mcp-connector`。
3. 安装完成后，**设置** 左侧会多出 **MCP 连接器** 一页。

> 也可以在终端运行 `dsh plugin add @nilzx/dsh-mcp-connector`。安装后如果页面里没看到，刷新一次页面或重启 Harness。

## 添加服务器

打开 **设置 → MCP 连接器**，点 **添加服务器**：

1. 起一个名字，例如 `github`。这个名字会出现在工具名里，之后不要随意改。
2. 选择连接方式：
   - **本地进程**：填写命令；参数（每行一个）和环境变量在 **更多连接设置** 里。
   - **远程端点**：填写服务器地址，例如 `https://mcp.example.com/mcp`。
3. 如果服务器需要密钥，在 **更多连接设置** 里填写环境变量或请求头；也可以先在凭据里保存，再引用为 `${credential:名称}`。
4. 停止输入后配置会**自动保存并重连**。卡片变成 **已连接**，并列出发现的工具。

保存后，智能体就能看到名为 `mcp__github__<工具>` 的工具。直接对它说“用 github 工具看看仓库里有哪些 issue”即可。

## 点开一个服务器之后

展开服务器不会再把连接参数一股脑列出来，而是三个子标签页：

- **工具设置**——默认权限，以及每个已发现工具单独一行。
- **作用域设置**——全局，或只在指定工作区可用。
- **更改配置**——名称、连接方式、登录方式，以及可选的高级选项。只有需要改连接方式时才进这里。

## 登录需要 OAuth 的服务器

很多远程 MCP 服务器（例如 Linear、Notion 一类的服务）通过 OAuth 登录：

1. **登录方式** 选择 **OAuth 登录**。授权范围、客户端 ID 等通常留空即可。
2. 卡片会变成 **需要登录**，并在浏览器里打开授权页面。
3. 同意后回到 Harness，状态变成 **已连接**。

登录信息保存在本机，重启不需要重新登录。想换账号时点 **忘记登录**，再重新登录。如果浏览器没有自动打开，点击卡片里的 **打开登录页面**。

## 设置每个工具能做什么

展开服务器，打开 **工具设置** 子标签页。每个已连接的服务器会列出它的工具，每个工具可以选：

| 权限 | 效果 |
|---|---|
| **默认** | 跟随该服务器的默认设置。 |
| **允许** | 直接执行。 |
| **询问** | 每次调用都先弹窗确认。 |
| **禁止** | 直接拒绝，不会执行。 |
| **隐藏** | 不提供给智能体，它根本看不到。 |

顶部一行是“其余工具的默认权限”。**按模式匹配的规则**（例如 `delete_*`）用于服务器尚未列出的工具，按顺序匹配，先命中的生效。

修改会自动保存。这些规则只影响智能体调用，不影响服务器本身。

## 选择服务器的作用范围

打开服务器的 **作用域设置** 子标签页，选择作用范围：

- **全局（所有会话）**——默认，所有会话都能使用这些工具。
- **仅在指定工作区**——只有在所选目录中运行的会话才会看到这些工具。

适合按项目使用的服务器：把工作用的服务器隔离在个人会话之外，或者把同一个服务的两个账号分别接到不同项目。

## 连接状态

| 状态 | 含义 |
|---|---|
| 已连接 | 工具可用。 |
| 连接中 / 重连中 | 正在尝试连接，稍等即可。 |
| 需要登录 | 等你在浏览器里完成登录。 |
| 失败 | 多次重试仍失败；修好后点 **重连**。 |
| 已停用 | 配置保留但暂不连接。 |

## 常见问题

**连不上怎么办？** 展开卡片看最近一次错误。本地进程常见原因是命令写错或缺少依赖；远程端点常见原因是地址不对、网络不通或需要登录。修好后点 **重连**。

**地址里没有路径。** 很多服务的 MCP 端点在 `/mcp`、`/ds/mcp` 这样的路径上，只填域名通常会返回 404，也不会发起登录。请从服务那里复制完整端点。

**智能体看不到工具？** 确认服务器是 **已连接**，并且工具权限不是 **隐藏** 或 **禁止**。新建一个会话会重新读取工具列表。

**修改没有生效？** 保存是自动的；如果状态提示保存失败，点 **重新加载** 再试。还不行可以停用再启用这个插件。

**登录一直失败？** 点 **忘记登录**，再点 **登录**，会得到一条全新的登录链接。

## 隐私与安全

- 工具调用的参数会发送到你配置的服务器，结果会回到当前会话。只连接你信任的服务器。
- 对会修改远端数据的工具，建议使用 **询问** 或 **禁止**。
- 登录凭据保存在本机，不会写进配置文件。

## 临时子代理与服务说明

“作用范围”页增加“临时子代理”选项，默认允许以兼容已有配置。个人记忆等仅属于主会话的服务可选择“禁止访问”（配置为 `delegation: deny`）。连接器会隐藏该服务的工具与使用说明，并在实际调用前再次拒绝子代理访问；工作区限制也会在调用前检查。普通主会话分叉仍可访问，禁止子代理时缺少会话元数据的调用也会被拒绝。

服务通过 MCP `initialize.instructions` 返回的说明现在会进入模型的系统提示，标明服务名，保留字面花括号而不做模板展开；访问范围不匹配、断开连接或工具全部禁止/隐藏时不注入。含服务名标签超过 32 KiB 的说明会使连接失败。说明用于指导模型，不等于强制每轮调用工具；服务自身仍需一致描述何时加载、刷新和保存数据。

## 自动逐轮上下文（未发布）

服务配置可选 `turnContext`，示例和字段见英文 README。它是通用连接器能力：配置工具名、固定参数、从 MCP `structuredContent` 到下次调用参数的 JSON pointer 映射，以及不可改变的主体字段；没有服务专用名称或文本解析规则。

启用后请新建未继承历史的会话。中立会话不会自动加载；第一次成功调用指定工具后，每个新用户轮以及进行中插入的新用户消息都会在生成前刷新。普通工具步骤不重复刷新。自动调用仍走当前会话的工具执行与权限检查，指定工具必须允许执行。刷新失败、取消、超时、主体或端点变化、访问范围受限、状态保存失败时阻断本轮。

会话状态保存在 dsh 的 `mcp_connector_context` 持久域中，只含端点指纹、映射参数和固定字段；返回的上下文以连接器来源记入会话。请随配置保留这份状态。旧会话缺失状态、历史继承/分叉不自动迁移；停用插件也会移除强制检查。该机制不代替服务端的可信主体绑定，也不把有限摘要变成完整变更流。目前已验证 dsh 0.2.2-rc.5 的默认执行器；不支持的执行器会阻断，不绕过权限。

## 增量交付与可信会话元数据（未发布）

`turnContext` 新增可选 `pagination` 和 `delivery`。分页全部成功且未超过总量限制才交付；读取位置在对应工具结果或连接器上下文确实进入当前模型会话后才确认。生成前中断、重启未交付会重新读取；压缩或替换已有上下文会触发配置的重载参数。侧表只保留游标、随机消息标识、摘要和上下文版本，不保存记忆正文。它证明内容已进入会话记录，不证明模型理解或用户阅读。

自动上下文会明确告知模型本轮已完成刷新，减少重复调用；即使增量为空，当前会话有价值的新记忆仍正常写入。提示不保证模型永不重复读取。旧提示格式的精确交付回执继续有效。

`runtimeMetadata` 可将真实会话及当前用户轮标识放入标准 MCP `_meta`；服务器需认证并信任连接器，模型工具参数不能提供或覆盖这些信息。显式 `captureTools` 才固定历史边界，成功后可用 `historyTools` 和本地 `mcp_connector_history` 读取；普通调用不提前冻结。明确声明未建立绑定的响应才能撤销尚未成功的候选边界，网络结果不确定则保留供重试。补录使用保留日志中的已完成原始对话，压缩摘要、系统提示、私有推理和工具输出不作为原始对话；缺失部分显式记录。

配置与限制见英文 README。以上仍是通用基础能力，尚未自动完成特定服务的初始化、分叉/恢复和用户确认流程；完整人格生命周期的真实 Web 验收仍待完成。


可选 `lifecycle` 将上述能力组成通用初始化流程，配置示例见英文 README。它在首次调用前持久记录会话归属，初始化期间拦截普通工具并缓冲模型输出，仅放行完整且获准的初始化工具调用；普通文字、推理文本和不完整输出不会交付。服务器报告就绪后，在同一轮强制完成首次上下文同步，再开放普通工作。配置的状态探测工具支持中断恢复，不能改变已绑定服务。

可信父会话标识可继承同一服务及固定历史引用，子会话从独立游标重新加载；父来源、端点或创建时间无法核实时拒绝。dsh 普通界面分叉目前不保存 `parentSession`，因此不能宣称其完整人格继承已经通过，需继续原会话。临时子代理不能看到或使用该服务及固定历史读取器。

`lifecycle.blockedTools` 可配置会复制父历史的宿主工具名，例如标准 dsh 中的 `[subagent_fork]`。会话启动工作流后，即使已经就绪，也会在工具执行前持续拒绝这些工具；普通 `subagent` 仍可用，只传本任务必要材料。应列全当前配置中的同类工具；名称不硬编码在连接器中。修改该拒绝策略不改变已有主体归属或读取位置，中立会话不受此列表影响。

对已绑定父会话的继承助手，或位于已启用工作流范围内的未知继承助手，另在创建和生成前拒绝；该兜底可能晚于正文落盘，不能替代复制前门禁。直接宿主 API、界面分叉、未列入配置的复制工具和同进程插件不属于上述复制前保证；全入口保证需要宿主提供创建继承种子之前的准入接口。完整真实 Web 验收仍在进行。

## 恢复实例的明确重关联（未发布）

顶层可配置 `recoveries`，具体字段见英文 README。先停止目标会话，由服务的私有用户通道批准精确恢复目标；保持原服务名称及持久会话，配置新端点，再通过已登录宿主的 `inspect-recovery` 管理操作取得创建时间、原固定字段及状态摘要。模型工具不能创建恢复授权或修改这些配置。

连接器先持久记录恢复日志，再调用获准的 MCP 工具并校验结构化的旧/新目标证明。随后保留主体和历史引用，清除旧游标、交付回执和人格确认，重新进入初始化；确认新实例的人格后才完整刷新记忆并开放普通工作。响应丢失或任一步写入中断都继续阻断，可用相同配置重启插件或通过私有 `retry-recovery` 操作继续。移除未完成操作不会解除门禁，旧的完成回执不能回退后续恢复。

固定字段中的永久主体必须列入 `stablePins`。配置中不得包含记忆正文或凭据。此功能不自动迁移其他宿主、合并多个可写副本或撤销旧实例的所有访问权；这些仍遵循服务端明确授权范围。设置面板会保留恢复配置；宿主报告上层配置覆盖时，需修改相应配置文件。


### 会话构造前准入（宿主可选能力）

宿主提供 `sessions.preparationAdmissionVersion = 1` 和同步 `session/preparing` 事件时，连接器会在目标会话构造及交付持久化之前检查继承来源，拒绝临时助手继承受保护正文以及来源不明的持久种子。设置 `lifecycle.requireCreationAdmission: true` 可强制要求该能力，缺失时启动失败，不静默降级。该策略不改变已有绑定指纹，也不增加逐轮写入；全新中立会话和全新助手仍可使用。

标准 dsh 0.2.2-rc.5 尚无此事件。[上游源码提案](contrib/dsh-session-admission/README.md)仅供审阅，不会自动安装。宿主仍可能在准入前读取来源、构造内存中的种子；承诺限于目标会话构造及落盘之前。恢复依赖可信宿主元数据和完整本地归属存储，不抵御有权限的插件或操作者伪造、删除存储。
